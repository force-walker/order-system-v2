# order_system_v2：別PC・別Wi-Fiからの接続とChatGPTへの問い合わせ

更新日: 2026-09-17
対象: 管理者に利用を許可された開発・検証ユーザー。
この文書にはパスワード、トークン、招待リンク、顧客データを含めない。

## 接続先

- アプリ: http://100.115.155.118:5173
- 接続確認: http://100.115.155.118:5173/health
- 正常な接続確認の表示: `{"status":"ok"}`
- ホストPC: `ikedakojiro-svd1323xpgb`
- 接続方式: Tailscale。自宅・会社・外出先など別のWi-Fiから利用できる。
- ホストPCの電源、インターネット接続、Tailscale、アプリ起動が必要。スリープ中は使えない。
- URLはTailscale内限定。URLを知っているだけでは接続できない。

## 初回：利用者が行うこと

1. https://tailscale.com/download から自分のPC用のTailscaleをインストールする。
2. 自分のアカウントでログインする。管理者のアカウントやパスワードを借りない。
3. 管理者から個別に受け取ったホストPCの共有招待リンクを開き、自分のアカウントで承認する。
4. PCのTailscaleアプリを接続状態にする。
5. ブラウザで `http://100.115.155.118:5173` を開く。
6. Login画面の「初めての方：新規登録」を選ぶ。
7. ユーザーID（半角英数字と `_ . @ + -`、3〜128文字）とパスワード（12〜128文字）、確認用パスワードを入力する。
8. 登録後のLogin画面で同じユーザーID・パスワードを入力する。ユーザーIDの大文字・小文字は区別しない。
9. 利用を終えたら、画面ヘッダーの「ログアウト」を選ぶ。

登録済みなら6〜7は不要。Tailscaleアカウントと、このアプリのユーザーID・パスワードは別物。
パスワードはChatGPTや管理者へ送らない。自分のブラウザの登録画面に入力する。
メール確認が必須の設定の場合は、登録が停止されるので管理者へ問い合わせる。

招待の承認と、PC上のTailscaleへのログインは同じ利用者のアカウントで行う。
管理者と同じネットワーク（tailnet）のメンバーとして既に許可済みなら、端末のログインとアクセス許可を確認する。
自分自身の別PCの場合は、自分が普段使うTailscaleアカウントにログインして使う。
接続端末にPython、Docker、ソースコードを入れる必要はない。
通常、ルーターのポート開放・ポート転送は不要。

## 2回目以降

Tailscaleを接続状態にしてアプリのURLを開く。ブックマークしてよい。
ホストPCの再起動後などに開けなくなった場合は、管理者にアプリの起動を確認してもらう。

## 接続できないとき

1. 一般のWebサイトが開けるか確認する。
2. Tailscaleが接続中か、招待を承認したアカウントでログインしているか確認する。
3. URLが `http://100.115.155.118:5173` か確認する。
   `localhost`、`127.0.0.1`、`192.168...`、`https://` に置き換えない。
4. `/health` のURLを開き、表示内容・エラーを記録する。
5. Windowsなら必要に応じてPowerShellで以下を実行する。設定変更は行わない。

```powershell
Test-NetConnection 100.115.155.118 -Port 5173
```

`TcpTestSucceeded : True` はそのPCからアプリのポートへ接続できることを示す。
Falseだけでは原因を断定できない。ホストの停止、共有未承認、アクセス規則、回線制限などを管理者に確認する。
`/health` が正常でもDBや全機能が正常とは限らない。画面内のエラーは別途記録する。
画面に「不正な注文ID」などが出る場合は、接続問題ではなく既存のアプリ不具合の可能性もある。

## ChatGPTに相談する方法

この文書の内容を利用者自身のChatGPTの新しいチャットへ貼り付け、末尾に質問を書く。
ローカルのファイルパスやアプリのURLだけを送らず、説明文そのものを渡す。
この開発チャットの内容が、他の利用者のチャットへ自動で伝わる前提にしない。
次の依頼文を一緒に使う:

> 上の文書をorder_system_v2の接続手順として参照してください。
> 私はホストPCとは別の場所・別のWi-Fiにいる利用者です。
> 初心者にも分かるように、接続とトラブル切り分けを一つずつ案内してください。
> 最初にPCのOS、Tailscaleのインストール・ログイン状態、共有招待の承認状況、表示エラーを確認してください。
> この文書を読んだだけで、あなたがホストPCや私のPCを確認・操作できるとは扱わないでください。
> 私の確認結果を根拠にしてください。URLを一般公開したり、VPNやファイアウォールを無効化したりする案内はしないでください。
> backend/.env、パスワード、認証トークン、Tailscale招待リンクを提出させないでください。
> 管理者側の確認が必要なら、確認すべき内容を短くまとめてください。
> 私の状況：［Windows / Macなど、どこまで完了したか、エラー文を記入］

問い合わせに画面画像を添える場合は、顧客名・金額・個人情報などを隠す。
チャットに接続説明を渡しても、そのチャットにTailscaleの接続権限が付くわけではない。

## 管理者向け：別ユーザーを許可する準備

共有はまだこの文書の作成だけでは実施されない。次の操作は管理者が行う。

1. Tailscale管理画面のMachinesで対象ホストを確認する。
2. 既存のアクセス規則を確認し、共有相手が必要なTCP 5173だけにアクセスする方針を設定・検証する。
   端末共有自体はポート5173限定ではない。広い既存の許可があれば、狭い許可を追加するだけでは制限できない。
3. 対象ホストのメニューでShare → Copy invite linkを選び、通常は一回限りのリンクを発行する。
4. 許可した本人にだけリンクを渡す。招待リンクをこの文書やChatGPTへ貼り付けない。
5. 本人の承認後、別Wi-FiのPCでアプリを開いてもらう。

アプリにはパスワード認証とサーバー側ログアウト失効がある。自己登録ユーザーはorder_entry権限。
Customerとの自動紐付けはなく、利用者別・顧客別のデータ分離は保証しない。
信頼できる開発・検証ユーザーのみを対象にする。顧客などへの本番提供には顧客別の権限制御等の整備が必要。
利用人数や業務利用についてはTailscaleの契約プランを確認する。
